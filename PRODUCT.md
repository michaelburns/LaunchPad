# Product

## Register

product

## Users
Mixed audience inside an IT organization. Authors (sysadmins, ops engineers) write and maintain PowerShell scripts. Launchers (helpdesk, business users) mostly pick a script, fill its parameters, and press launch; many never read the code. Administrators grant roles and categories. Everyone wants to know, at a glance, what ran, what's running, and whether it worked.

## Product Purpose
LaunchPad is a PowerShell command center: one secure place to store, launch, schedule, and audit scripts with role- and category-based access. Success is a non-technical person running a script confidently without help, and an operator spotting a failure within seconds of opening the app.

## Brand Personality
Precise, calm, trustworthy. Terminal DNA (keyboard-first, monospace for data and code, sodium-amber runway accent for "live") but finished to the standard of Linear or Raycast. It should feel like mission control, never like a hacker toy.

## Anti-references
- Stock Bootstrap admin templates and generic SaaS dashboards (hero metric cards, gradient accents).
- "Hacker" green-on-black terminal cosplay.
- The raw Hangfire dashboard look.

## Design Principles
1. Status first: what ran, what's running, what failed must be readable in under three seconds on every screen.
2. Safe for launchers, fast for authors: obvious primary actions and confirmations for non-technical users, keyboard paths for experts.
3. Data carries the design: real run history, real timings, real output, not decoration.
4. Amber means live: the accent is reserved for running state and the single primary action.
5. One vocabulary: the same button, status, and table language on every page.

## Accessibility & Inclusion
WCAG 2.2 AA. Status is never color-only (always a label or glyph). Full keyboard operation. Respect prefers-reduced-motion.
